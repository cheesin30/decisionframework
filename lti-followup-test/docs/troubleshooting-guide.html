LTI Follow-up — Power Automate Troubleshooting Guide

How to diagnose and fix a failed LTI Follow-up Sender flow run. For consultants and anyone supporting the workshop follow-up system.

1. What the flow does (in 20 seconds)

When an adviser submits the LTI follow-up Form, the flow rebuilds the exact .ics filename from the Firm + Date baked into the QR, fetches that file (and a static how-to PDF) from SharePoint, and emails them to the adviser. If any step fails, a diagnostic email is sent to the operator and the run is marked Failed (red) in run history.

Trigger: When a new response is submitted (Forms) -> Get response details -> Compose filename {Firm}_LTI_Follow_Up_{yyyy-MM-dd}.ics -> Try (scope) -> Get file content using path ( .ics from /LTI/Generated ICS/ ) -> Get how-to PDF ( /LTI/Assets/LTI_Calendar_How-To.pdf ) -> Send advisor email ( 2 attachments ) -> Catch (scope, runs only if Try fails) -> Filter failed actions -> Compose error -> Send diagnostic email -> Terminate (Failed)

2. First response: read the failed run

  1. Go to make.powerautomate.com → My flows → LTI Follow-up Sender → Run history (or open the flow inside Solutions if imported that way).
  2. Open the most recent Failed (red) run.
  3. The failed action is highlighted red. Click it → expand Inputs and Outputs / error to see the message.
  4. Cross-check against the diagnostic email the run sent to the operator — it already contains the key facts:
Constructed filenameThe exact .ics name the flow tried to fetch — compare this to the real file in SharePoint.
FirmThe Firm value from the QR (case-sensitive; may contain underscores).
Workshop dateThe date value from the QR (must be yyyy-MM-dd).
Adviser emailWhere the pack was meant to go — check for typos.
Timestamp (SGT)When it failed (Asia/Singapore).
Error messageThe raw error from the failed action.

4. Connection & permission problems

The flow uses three connections. An expired or wrong-account connection is a common cause of sudden, repeated failures across many runs.

To fix a connection: make.powerautomate.com → gear / Connections (or Data → Connections). Find the one with a red status → ⋯ → Fix connection / Reconnect and sign in. Then resubmit the failed runs.

Sender note. During the test phase the email sends from cheesin.foong@capitalgroup.com. In production this becomes the Capital Learning shared mailbox (the send action changes to Send an email from a shared mailbox (V2)). If the sender looks wrong, check which action/connection is in use before changing anything.

5. Re-running a failed submission (so the adviser still gets their pack)

After you fix the cause, you usually don't need the adviser to scan again:

  1. Open the failed run in Run history.
  2. Click Resubmit (top of the run) — this replays the flow with the same original form submission (same adviser, Firm, date).
  3. Confirm it turns green and the adviser receives the email with two attachments (the .ics + the how-to PDF).
When a resubmit will NOT help: if the failure was a wrong value from the QR (wrong Firm/date) or a typo in the adviser's email address, resubmitting replays the same bad data. Fix the QR / ask the adviser to submit again with the correct details instead.

6. The filename contract (root cause of most failures)

The flow and the calendar tool must agree on one filename, exactly:

{Firm}_LTI_Follow_Up_{yyyy-MM-dd}.ics e.g. DBS_LTI_Follow_Up_2026-06-30.ics
  • Firm is the slugified firm name from the calendar tool — case-sensitive, and it can contain underscores (e.g. DBS_Private_Bank). The generated filename is the source of truth: copy the Firm segment verbatim into the QR, don't retype it.
  • Date is yyyy-MM-dd with hyphens — 2026-06-30, never 30-06-2026 or 2026/06/30.
Composed by: concat(Firm, '_LTI_Follow_Up_', WorkshopDate, '.ics') — Firm and Date are passed through untouched, so whatever the QR baked in is exactly what gets fetched.

7. Escalation

If a run keeps failing after the fixes above, capture: the run URL from run history, the failed action name, the raw error message, and the diagnostic email. Then escalate to the flow owner (cheesin.foong@capitalgroup.com during the test phase).
